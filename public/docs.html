System Architecture & Modern Stack

FormForge is custom-built on top of the lightning-fast Cloudflare v8 Serverless Network. Designed for incredible global reliability with absolute zero cold starts and no connection pooling overhead:

⚡

Cloudflare Workers

Runs directly inside Edge isolates globally. Delivers sub-10ms operational response latency.

📀

Cloudflare D1

Enterprise-grade distributed SQLite storage. Fully relational with instant automated backups.

🖋️

Drizzle ORM

Highly performant type-safe SQLite query engine tailored for strict edge execution isolates.

⚛️

Next.js & OpenNext

Modern React 19 visual administration interface fully compiled to execute flawlessly at edge.

Decoupled Request-Scoped Database Strategy: A major hazard in traditional serverless deployments is importing global PostgreSQL connection pools that trigger fail-states during automated build processes like next build. FormForge elegantly eliminates this by instantiating the SQLite D1 client entirely within dynamic route handlers via getDb(request, env). During static pre-compilation, FormForge bypasses database queries safely!

Environment Variables Reference

Configure secret properties and bindings directly inside your Cloudflare panel (Worker → Settings → Variables and Secrets) or your local wrangler.jsonc configuration:

Secret Variable Requirement Purpose & Specifications
AUTH_SECRET Required A secure 32+ character hexadecimal cryptographic key. Essential for signing and verifying JWT authentication tokens for dashboard management sessions.
DB Required The Cloudflare D1 Database binding pointer. This is configured natively in wrangler.jsonc or the Cloudflare dashboard to connect to your global SQLite layer.
RESEND_API_KEY Optional Your secure API key from Resend.com. Enable this if you wish to receive automated email notifications when forms are ingested. Bypassed safely when completely blank.
RESEND_FROM Optional Validated sender address configured within your Resend portal (e.g. FormForge System <notifications@yourcompany.com>).

D1 Database Setup & Local Commands

For local development workflows, custom git pipelines, or manual Wrangler CLI control, execute these exact terminal commands:

Local Terminal Console
Bash

# 1. Authorize your interactive Cloudflare CLI session

$npx wrangler login

# 2. Provision your production D1 SQLite instance on Cloudflare

$npx wrangler d1 create formforge-db

Note: The terminal will print a distinct database_id (e.g. 4c5b162a-8c3a...). Copy and place this exact ID directly into your wrangler.jsonc file!

# 3. Generate structured SQL migration blueprints via Drizzle Kit

$npx drizzle-kit generate

# 4. Commit migration blueprints to remote Cloudflare D1 production database

$npx wrangler d1 migrations apply DB --remote

# 5. Compile and deploy your Worker logic directly to edge nodes

$npm run deploy

Want to experiment completely offline? Simply execute npm run dev. Drizzle integration routines will securely interface with an isolated local SQLite `.sqlite` stub automatically maintained inside your hidden .wrangler workspace folder.

2. Programmatic JavaScript AJAX Execution

Incorporate structured asynchronous JSON payload posting inside your active React, Vue, Svelte components, or mobile applications with complete custom state handling:

JavaScript 
const transmitFormSubmission = async (event) => {
  event.preventDefault();
  
  const formPayload = {
    email: "customer@example.com",
    name: "Samantha Wright",
    message: "Inquiring about custom enterprise support plans.",
    _honeypot: "" // Absolute requirement: MUST remain completely empty
  };

  try {
    const response = await fetch("https://your-worker-subdomain.workers.dev/api/submit/contact_slug_123", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "Accept": "application/json"
      },
      body: JSON.stringify(formPayload)
    });

    const returnedData = await response.json();
    
    if (response.ok && returnedData.success) {
      alert("Submission successful! Recorded ID: " + returnedData.submissionId);
    } else {
      console.error("Submission rejected:", returnedData.message);
    }
  } catch (error) {
    console.error("Critical network communication exception:", error);
  }
};

Troubleshooting FAQ & Build Solutions

Commonly observed operational edge errors, local wrangler setup hurdles, and instant build-time configurations:

Error: "DATABASE_URL is required" during Next.js compile

This behavior is typically encountered when reusing legacy codebase templates that attempt to connect to external PostgreSQL database connections at the global Node.js module root. FormForge eliminates this codebase flaw completely. All database logic uses drizzle-orm/d1 and is safely wrapped inside dynamic runtime operations via getDb().

Error: "D1 database is not bound" or `env.DB` throws undefined

Ensure your deployment or local workspace has bound your Cloudflare D1 integration exactly under the uppercase moniker DB. Inspect your local wrangler.jsonc configuration table to verify that it matches this structure:

JSON 
"d1_databases": [
  {
    "binding": "DB",
    "database_name": "formforge-db",
    "database_id": "your-actual-uuid-from-wrangler-d1-create"
  }
]

Requests consistently fail with a "CORS Origin Rejected" status response

This happens when you have filled the "Origin Allowlist" settings field inside your administrative bucket panel, but are attempting to post input entries from an unauthorized local development server. Either add your local origins (like http://localhost:3000 or http://127.0.0.1:5173) into your allowlist, or leave the allowlist entirely blank to accept entries from anywhere.

Does the deployment require or depend on my GitHub username?

Absolutely not. The primary GitHub repository link acts purely as a cloneable source blueprint during your initial one-click setup. When you authorize Cloudflare, all active runtime workers, databases, and continuous deployment webhooks are provisioned entirely independently inside your personal account space.
